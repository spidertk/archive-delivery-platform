# jun-2 交付性能与扩容评估

本轮 343 个源包、89 个交付包全部交付，提交到完成耗时 **14.18 分钟**，平均 **6.28 包/分钟**。这台机器为 2 vCPU、3.54 GiB RAM、约 491.8 GiB 磁盘。**6000 包每轮容量已配置；本轮实测规模为 89 包。** 按当前保留策略和本轮大小分布推算，6000 个交付包需要约 **1.25 TB** 业务文件空间，超过现机容量，需要先扩容再放量。

## 测量口径

交付窗口为北京时间 2026-11-21 03:52:37 至 2026-11-21 04:06:48，同组运行并发上限为 3，gzip level=5，最终包上限 100 MiB。源缓存保留，准备阶段可命中同机缓存；本轮速率适用于这一实际路径。独立验收另外真实 GET 了全部来源和目标，并下载 FTP 文件。

流水线执行中于 2026-11-21 04:02:00 应用流式优化，早期任务和后续任务使用的校验实现不同。全程还执行了一次实包对照；资源采样包含发布、执行与验收，以下内存数值只取交付窗口的 47 条采样。全程原始记录见 [resources.jsonl](resources.jsonl)，计算结果见 [performance-metrics.json](performance-metrics.json)。

## 本轮优化及剩余瓶颈

原校验先 `getmembers`，再对每个 requestId 扫描全部成员并回读 gzip。现改为单次顺序读取并建立协议索引，保留 requestId、UTC 纳秒时间、providerCode、响应模式和必需文件检查；merge 也改为一次顺序安全解包。

对同一份 71.84 MB 已交付文件进行只读对照：旧校验 **77.92 秒**，新校验 **1.64 秒**，该阶段约快 **47.6 倍**。两次协议校验均通过、文件 SHA 不变。测量顺序为新实现后旧实现，且同时存在真实交付负载，因此该比值仅描述这份文件的校验耗时。[原始对照](protocol-benchmark.json)。

优化发布后启动的 47 个 repair 节点平均耗时 **12.37 秒**。内部平均：gzip 封包 8.45 秒、请求修复 1.59 秒、协议校验 1.22 秒、工作区复制 0.77 秒。gzip 占内部总耗时约 69%，后续扩容应优先增加 CPU 与内存，再观察 IO；这些任务输入不同，不能把其平均值当成严格的整链路前后对照。

FTP 正常上传路径由两次完整回读合并为一次 RETR，复核通过后原子发布；本轮平均约 0.90 秒。还修复了多 Worker 容量检查竞争、JVM heap 无明确上限、classic builder 不兼容及看板资源打包问题。Worker/API heap 均设置为 256 MiB 上限，PowerJob heap 为 384 MiB；这些为 JVM heap 限制，仍需为 native 内存和 Python、数据库预留空间。

## 放量边界

本轮最终保留：source-cache **6.060 GiB**、FTP 最终文件 **5.591 GiB**、本地 FTP 回验副本 **5.591 GiB**；本单工作目录约 **10.37 MiB**，主要为 manifest。三类主要数据合计 17.24 GiB。当前剩余磁盘约 380.5 GiB。

| 后续口径 | 按本轮分布估算的三类数据空间 |
| --- | --- |
| 6000 个交付包 | 约 1.25 TB |
| 6000 个源包 | 约 324 GB，约对应 1557 个交付包 |

估算尚需叠加系统、镜像、其他批次和解包 staging 峰值。若目标是 6000 个交付包，建议准备至少约 1.5 TB 可用数据空间，按 2 TB 数据盘规划更有余量；CPU/RAM 先以 4 vCPU、8 GiB 作为下一阶段评估起点，扩容后重新测定并发。当前同组并发保留为 3，避免用扩大并发掩盖 CPU、分页与磁盘限制。

按本轮全程速度线性估算，6000 个交付包约 15.9 小时；冷来源下载、更大输入、外部限流及持续压缩负载可能改变结果。建议依次以 200、1000、3000、6000 个交付包验收，记录完整日截止时间、P95 节点耗时、磁盘余量、分页、重试与全部外部 SHA 检查。每档通过后再增加数量，6000 包的实际通过结论留待该档完整验收。

后续同机观察可执行：

```bash
python3 scripts/observe-delivery.py --output docs/evidence/JUN2-followup/resources.jsonl --duration 3600 --interval 15
```

该观察器有界采集资源和 PG 状态，不改变交付事实。本轮观测结束时间以 resources.jsonl 最后一条记录为准；本报告说明本轮运行窗口的稳定性。
